# 用户等级与角色体系

## Goal

为用户模型增加等级和角色体系：用户等级默认 `0`，角色区分管理员和普通用户，并将该信息贯通数据库、API、权限判断和前端会话展示/路由保护。

## Requirements

- 用户数据模型新增 `level` 字段，非空，默认值为 `0`，历史用户迁移回填为 `0`。
- 用户数据模型新增角色字段，至少支持 `admin`（管理员）和 `user`（普通用户），默认角色为 `user`。
- 当前用户、登录/注册响应、用户资料相关 DTO 需要返回必要的 `level` 和 `role` 信息。
- 后端管理员权限判断统一基于角色，不得在多个位置散落字符串判断。
- 管理员入口/管理 API 仅允许管理员访问；普通用户访问时返回明确权限错误。
- 前端会话状态、类型定义、路由守卫和管理员入口按 `role`/`level` 更新。
- 初始化/种子数据/创建管理员方式需要支持设置管理员角色。

## Acceptance Criteria

- [ ] 新注册用户默认 `level = 0` 且 `role = user`。
- [ ] 数据库迁移能为已有用户补齐默认等级和角色。
- [ ] 管理员账号可访问管理员功能，普通用户不可访问。
- [ ] 前端能读取并使用当前用户的 `level` 和 `role`，不会因字段缺失报错。
- [ ] 后端测试覆盖默认值、权限判断、管理员/普通用户访问分支。
- [ ] 前端类型检查通过，并覆盖管理员入口显示/隐藏或路由保护场景。

## Technical Notes

- `level` 与 `role` 是跨层契约字段，实施前需明确数据库字段名、API 字段名、枚举值和默认值。
- 建议集中定义角色常量/枚举和权限 helper，避免字符串重复。
- 如果已有 `is_admin`、`is_moderator` 或状态字段，实施前需梳理兼容/迁移策略，避免权限回归。
- 该任务涉及权限安全，检查时必须覆盖管理员、普通用户和未登录用户三类访问路径。
