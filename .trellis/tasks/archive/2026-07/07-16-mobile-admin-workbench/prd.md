# 优化移动端管理工作台

## Goal

让管理员在手机上打开工作台时，能在首屏快速判断社区是否需要处理，并以适合触控和窄屏浏览的密度查看核心运营数据；不改变现有数据含义、权限边界和桌面端工作流。

## Background

- 用户提供的 2026-07-16 iPhone Safari 截图显示：页头与摘要区纵向留白过大，四项摘要在窄屏退化为四个全宽单列块，首屏只能看到部分数据，整体仍像被压窄的桌面后台。
- 工作台由 `apps/web/src/pages/admin/AdminDashboardPage.vue` 挂载 `AdminWorkbenchPanel.vue`；数据来自现有 `useAdminSystem()` 查询，无需新增接口。
- `AdminWorkbenchPanel.scss:428` 在 `680px` 以下把摘要、快捷入口和骨架屏统一改为单列；摘要项仍保留较高的最小高度，直接造成截图中的低信息密度。
- `AdminConsoleShell.scss:315` 在 `860px` 以下切换为移动端顶栏、抽屉和固定底部导航；管理员可见六个入口，底栏按可见项数量等分。它与工作台内容共同构成截图中的完整移动体验。
- 项目产品定位要求后台界面保持冷静、可信、便于扫描，避免装饰性 SaaS 仪表盘、过度圆角、玻璃拟态和无实际数据的视觉元素。

## Requirements

### R1. 移动端信息层级

- 手机窄屏下优先呈现“是否有待处理事项”和四项真实运营摘要，减少不承载信息的纵向留白。
- 四项摘要不得继续以四个高大的全宽单列块呈现；在 `320px` 至 `430px` 宽度内应形成可快速扫读、无横向溢出的紧凑布局。
- 待处理状态、异常状态和正常状态必须继续使用现有真实数据与语义色，不制造趋势、图表或虚构指标。

### R2. 内容与交互完整性

- 保留工作台现有的加载、错误、无待办、最近管理动态与快捷入口状态。
- 指标与快捷入口仍可进入现有管理路由，核心触控目标不小于 `44px × 44px`。
- 不依赖 hover 才能理解或操作；保留键盘焦点反馈和减少动态效果偏好。

### R3. 响应式边界

- 改动以移动端结构适配为主，桌面端的四列摘要、双栏工作区和侧边导航行为不得发生非预期变化。
- 同步优化 `860px` 以下的移动顶栏与六项底部导航，但不改变入口数量、顺序、权限、文案配置键或路由。
- 至少覆盖 `320px` 窄屏、常见 `390px` iPhone 视口、横屏/小平板过渡区以及桌面宽度。
- 页面需处理 iOS 安全区与固定底部导航占位，不得遮挡最后一项内容。

### R4. 视觉与品牌约束

- 继续使用现有设计令牌与 Ant Design 图标体系；主操作/选中态遵循 `#409EFF` 规范，不新增渐变主按钮。
- 不替换、重绘、重命名或改动正式 Logo、favicon 及其默认路径。
- 不用装饰性大卡片、玻璃拟态或无意义动效掩盖信息密度问题。

### R5. 范围控制

- 不修改 API、数据库、统计口径、权限判断、路由结构或后台可配置文案机制。
- 实现范围限于工作台、管理控制台移动外壳及其定向前端验证，不延伸到其他后台业务页内容。

## Acceptance Criteria

- [x] AC1：在 `390 × 844` 视口中，页头与四项运营摘要可在首屏内完整扫读，并能看到下一核心区块的入口或标题。
- [x] AC2：在 `320px` 宽度下，无横向滚动、文本重叠或被底部导航遮挡；所有核心入口具备至少 `44px` 的触控区域。
- [x] AC3：待处理举报、社区用户、主题与回复、失败任务的数值、说明、状态语义和目标路由与当前实现一致。
- [x] AC4：加载、请求失败、无待办、有待办、无审计记录和有审计记录状态均保持可读可用。
- [x] AC5：在 `1440px` 桌面宽度下，现有侧栏、顶栏、四列摘要和双栏工作区未出现布局回归。
- [x] AC6：未改动受保护品牌资源，主色/选中态继续遵循现有令牌；键盘焦点与 `prefers-reduced-motion` 行为保留。
- [x] AC7：实现阶段完成后通过 `pnpm typecheck:web`，并对 `320px`、`390px`、`860px` 过渡点和桌面视口做定向视觉检查。

## Out of Scope

- 新增运营指标、趋势图或后端聚合接口。
- 重做其他后台业务页面的内容布局。
- 全站导航、全局主题或品牌资产改版。
- 原生 App、离线能力或手势导航。
