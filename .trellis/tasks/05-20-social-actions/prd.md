# 社区互动动作补齐：点赞、收藏、转发与邀请入口

## Goal

补齐社区核心互动动作，让主题、回复/帖子在列表页和详情页都具备可用、可追踪、权限正确的点赞、收藏/书签、转发/分享与邀请入口，并与登录态、通知、私密版块权限保持一致。

## Requirements

- 主题与回复/帖子支持点赞/取消点赞；接口需幂等，计数与当前用户状态一致。
- 主题支持收藏/取消收藏或书签；收藏状态应在列表、详情和用户相关页面可复用。
- 转发/分享至少支持复制可访问的规范链接；详情页内的回复应能复制到楼层/锚点链接。
- 游客可以看到公开内容的计数和分享入口，但点赞、收藏、邀请等写操作需要登录，并提供清晰登录提示。
- 邀请入口不重复实现完整邀请版块流程；应与既有任务 `05-18-public-invite-boards` 的「我的邀请」/邀请版块能力对齐。
- 私密/邀请版块内容的分享链接不得绕过后端权限；未授权用户打开时应返回明确无权限或不存在状态。
- 前端交互需要处理 loading、禁用、失败回滚、重复点击、防抖和乐观更新。
- 后端需要保证计数更新事务安全，避免重复点赞/收藏造成计数漂移。
- 互动事件应按产品需要接入通知：例如被点赞/收藏时通知作者，自己的动作不通知自己。

## Acceptance Criteria

- [ ] 登录用户可在主题列表、主题详情和回复/帖子处点赞/取消点赞，刷新后状态和计数保持正确。
- [ ] 重复点击或重复请求不会产生重复记录，也不会让计数为负或漂移。
- [ ] 登录用户可收藏/取消收藏主题，并能在后续页面或 API 中读取收藏状态。
- [ ] 游客触发点赞/收藏/邀请写操作时被引导登录，不出现静默失败。
- [ ] 转发/分享复制的链接能打开对应主题；回复链接能定位到对应楼层或锚点。
- [ ] 私密/邀请版块链接不会向未授权用户泄露标题、内容或计数之外的敏感信息。
- [ ] 前端类型检查、后端测试和互动相关 smoke/组件测试覆盖 Good/Base/Bad cases。

## Technical Notes

- 该任务是跨层功能，实施前需要明确 API 字段：`liked_by_me`、`like_count`、`bookmarked_by_me`、`bookmark_count`、`share_url` 或等价命名。
- 先复用现有交互/通知规范，避免在组件内硬编码散落的计数字段和状态转换。
