# 内容安全：敏感词过滤、举报与审核

## Goal

建立内容安全闭环：用户提交内容时进行敏感词过滤/拦截，社区成员可以举报违规内容，管理员/审核员可在审核队列中处理举报并留下审计记录，避免违规内容无管控地发布和传播。

## Requirements

- 敏感词规则支持至少三类动作：阻止发布、进入待审核/隐藏、替换或提示修改；首版可选择其中一到两类，但必须明确行为。
- 过滤范围至少覆盖主题标题、主题正文、回复/帖子正文；如扩展到昵称、版块名、简介等，需要同步写入验收标准。
- 文本过滤需做基础规范化，避免大小写、全半角、空白/标点插入导致明显绕过。
- 发帖/编辑接口在命中规则时返回可理解的错误或审核状态，不应泄露完整敏感词表。
- 用户可从主题/回复/帖子操作区发起举报，选择原因并填写补充说明；重复举报同一对象应幂等或明确合并。
- 后端维护举报、审核队列、内容隐藏/恢复/驳回、处理人、处理时间和审计日志。
- 管理员/审核员可查看待处理举报，执行隐藏、恢复、驳回、标记已处理等操作；普通用户不能访问审核台。
- 被隐藏或待审核内容在列表、详情、搜索、用户内容页的可见性需一致，不能只在单个页面隐藏。
- 与用户角色任务对齐：若审核员角色未完成，首版先由管理员角色处理。

## Acceptance Criteria

- [ ] 发布/编辑主题或回复命中敏感词时，后端按规则阻止或标记待审核，前端展示清晰提示。
- [ ] 敏感词过滤覆盖标题与正文，并有绕过样例的单元测试。
- [ ] 登录用户可举报公开可见主题/回复/帖子；游客举报写操作需登录。
- [ ] 重复举报不会刷爆队列或产生不可控重复记录。
- [ ] 管理员/审核员可在审核台查看待处理举报并执行处理动作。
- [ ] 处理动作会更新内容可见性，并写入审计日志。
- [ ] 被隐藏/待审核内容不会在 Feed、搜索、用户内容列表和详情页中对普通用户泄露。
- [ ] 后端权限测试覆盖管理员/普通用户/未登录用户；前端类型检查和审核台 smoke/组件测试通过。

## Technical Notes

- 这是 P0 安全任务，实施时优先保证后端边界，再补前端体验。
- 需要明确模型/状态：`report.status`、`moderation_action`、`content_visibility`、`audit_log` 或等价字段。
- 敏感词表可先使用数据库或配置文件，但必须考虑热更新/部署流程；不应把真实敏感词样本大量写进公开测试快照。
- Relevant specs: backend/frontend `moderation-admin-safety.md`，backend `database-guidelines.md`、`error-handling.md`，frontend `post-actions.md`，guides `cross-layer-thinking-guide.md`。
