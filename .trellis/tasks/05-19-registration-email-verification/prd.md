# 注册邮件验证码激活

## Goal

注册流程接入真实邮件发送配置：用户提交注册信息后收到邮箱验证码，输入正确验证码后完成账号激活，并能正常登录/使用已认证功能。

## Requirements

- 后端提供真实邮件发送配置，支持通过环境变量配置 SMTP/邮件服务（host、port、账号、密码、发件人、TLS/SSL 等），不得硬编码密钥。
- 注册时创建待激活用户或待验证注册记录，并生成一次性邮箱验证码。
- 验证码需要有过期时间、重发限制、错误次数/频率控制，并避免明文长期存储。
- 邮件发送失败时返回可处理的业务错误，并记录可排查日志；测试环境保留可替代的 fake/in-memory 邮件实现。
- 前端注册页支持“提交注册信息 → 输入验证码 → 激活成功”的完整流程。
- 激活成功后用户状态更新为可登录/可使用状态；未激活用户不能绕过验证码完成登录。
- 重复邮箱、验证码错误、验证码过期、发送过频、邮件配置缺失等场景有明确提示和测试。

## Acceptance Criteria

- [ ] 使用真实 SMTP/邮件服务配置时，注册邮箱能收到验证码邮件。
- [ ] 用户输入正确验证码后账号被激活，并能正常登录。
- [ ] 未激活账号无法直接完成登录或进入已认证功能。
- [ ] 错误/过期验证码、重复邮箱、邮件发送失败、重发过频均返回明确错误。
- [ ] 后端单测覆盖注册、发送验证码、验证激活、异常分支。
- [ ] 前端注册/验证码 UI 覆盖主要交互路径，并更新/新增冒烟测试。
- [ ] 部署/环境变量说明同步更新，密钥不进入仓库。

## Technical Notes

- 建议优先复用现有 auth service/router/schema/test 结构；若新增 email service，应与配置层和测试替身解耦。
- 验证码建议只保存 hash、过期时间和尝试次数；不要在日志中输出验证码或邮件密钥。
- API 契约需明确：注册请求、重发验证码、验证激活、当前用户状态字段。
- 该任务是跨层任务，实施前必须阅读 fullstack context 中注入的 backend/frontend/guides 规范。
