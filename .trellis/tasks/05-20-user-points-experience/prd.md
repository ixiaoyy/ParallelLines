# 用户积分与经验成长体系

## Goal

在既有「用户等级与角色体系」任务基础上，补齐积分、经验和成长规则：用户行为可产生可审计的积分/经验变化，等级可按规则计算或升级，并在 API 与前端用户资料中稳定展示。

## Requirements

- 明确积分与经验的领域含义：积分可作为可消费/可调整余额，经验用于等级成长；如首版不区分，需要在实现前写清楚等价策略。
- 定义用户字段与默认值：例如 `points_balance`、`experience_total`、`level`，新老用户默认值可迁移回填。
- 定义等级规则：每级所需经验、升级边界、最高等级或开放式规则，规则应集中配置，不能散落在 UI。
- 定义积分/经验来源 MVP：注册激活、发主题、回复、内容被点赞、邀请接受等；需要包含每日上限或幂等规则，防止刷分。
- 建立积分/经验流水，记录来源类型、关联对象、变更值、操作者、幂等键和时间，便于审计和回滚。
- 当前用户、公开用户资料、作者卡片等 DTO 返回必要的等级/积分/经验展示字段。
- 管理员可做必要的人工调整或重算入口；普通用户不能伪造积分/经验变化。
- 与父任务 `05-19-user-levels-roles` 的角色/权限字段保持一致，不重复定义角色枚举。

## Acceptance Criteria

- [x] 新注册/迁移用户拥有稳定默认积分、经验和等级，不因字段缺失导致登录或资料页报错。
- [x] 发主题、回复、获赞等 MVP 行为能按规则增加经验/积分，重复事件不会重复发放。
- [x] 等级根据经验规则正确变化，边界值测试覆盖升级前、刚升级、超过多级场景。
- [x] 积分/经验流水可追踪每次变化来源，并支持幂等校验。
- [x] 前端能在当前用户信息、公开资料或作者信息处展示等级/经验，不使用假数据。
- [x] 后端测试按降级策略覆盖默认值、发放规则、幂等和等级边界；每日上限/管理员分支保留到详细测试阶段。

## Technical Notes

- 该任务作为 `.trellis/tasks/05-19-user-levels-roles` 的子任务；角色/管理员权限以父任务最终契约为准。
- 实施前需要决定 `level` 是存储字段还是由 `experience_total` 派生；若存储，必须定义重算/同步策略。
- 积分/经验变动应优先通过服务层统一入口发放，不允许各 router 直接改用户数值字段。
- Relevant specs: backend `database-guidelines.md`、`error-handling.md`，frontend `auth-user-session.md`、`type-safety.md`，guides `cross-layer-thinking-guide.md`。
