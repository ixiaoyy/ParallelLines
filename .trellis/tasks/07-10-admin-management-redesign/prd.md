# 后台管理改版 PRD（设计阶段）

## Goal

为 ParallelLines 后台建立一套统一、清晰、可扩展的管理端信息架构与视觉系统，先完成可评审设计稿，再进入代码实现。

## Known Facts

- 当前独立后台路由包括：后台首页、访问统计、用户管理、内容审核。
- 后台首页还承载系统状态、任务队列、邮件日志、最近审计与任务提醒。
- 现有页面沿用前台顶栏，缺少后台专属导航与统一页面模板。
- 最新访问统计截图存在信息层级倒置、日期状态重复、卡片嵌套和内容密度失衡。
- 用户要求这是后台管理部分的大改版，不能只做局部 CSS 调整。
- 正式品牌 Logo、主按钮蓝 `#409EFF` 与现有品牌资产不可擅自替换。

## Assumptions

- 首轮设计稿以桌面端 `1440 × 1024` 为主，展示“访问与用户增长”代表页，同时定义后台壳层与导航方式。
- 选定方向后，再补用户管理、审核台和系统概览的关键页面稿及移动/窄屏规则。
- 后台仍属于同一站点，不另造品牌；复用现有颜色、字体、图标与设计令牌。

## Open Questions

- 管理员最常用的首要任务排序需要在方向选择后确认。

## Decisions

- 2026-07-10：用户选择首轮方案 1“运营控制台”。
- 后台采用独立管理端壳层：固定左侧导航 + 轻量顶部工具栏，不继续显示前台搜索/发布顶栏。
- 在改生产代码前，先交付覆盖五个主要入口的独立可点击原型供统一评审。

## Requirements

- 先提供 3 套有明显结构差异的视觉方向，用户选定后才实现代码。
- 方向稿必须覆盖后台壳层、主导航、页面标题/操作区、核心指标、趋势图和次级列表。
- “用户增长”必须清晰可见，并明确“不含马甲账号”，但不能压倒访问统计的核心层级。
- 后台模块至少能容纳：首页概览、访问与增长、用户管理、内容审核、系统运行。
- 避免整页大卡套小卡、重复状态、无意义大留白和同权卡片网格。
- 桌面端优先，同时为 940px 与 390px 预留结构性响应方案。

## Acceptance Criteria

- 用户能从三张独立设计稿中明确选择一个方向。
- 每张稿在 2 秒内能识别当前模块、主要指标、主要操作和后台导航。
- 设计稿使用真实中文后台文案与合理示例数据，没有占位符或虚构功能堆砌。
- 选定方向可扩展到用户管理、审核和系统面板，不依赖单页特例。
- 未经用户选择，不修改生产 UI 代码。

## Out of Scope

- 本阶段不实现 Vue/SCSS，不提交前端改版代码。
- 不改变后端 API、权限模型、统计口径或数据库。
- 不替换 Logo、favicon 或主品牌色。

## Technical Notes

- 现有前端为 Vue 3、Ant Design Vue、SCSS、CSS variables、ECharts。
- 设计实现时应保留现有查询、ECharts refs、ResizeObserver 与管理员权限边界。
- 相关规范：`.trellis/spec/frontend/admin-dashboard.md`、`.trellis/spec/frontend/analytics-data-explorer.md`。
